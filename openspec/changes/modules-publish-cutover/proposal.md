# Proposal — modules-publish-cutover

> Slice `modules-publish-cutover` of enhancement `0011` — the last implementation slice of the 0010/0011 pair. Decisions D13, D15 (+ 0010 D17). This repo has no OpenSpec workspace today; this change creates its first (proposal/design/tasks, no spec tree) and records with `openspec_ref: "modules/modules-publish-cutover"`.

## Why

The fleet still publishes through a checksum ledger that decides versions by hashing files. D15 measured why that has to go: `versions.yml` lists 20 modules and **two** still carry a checksum (`seerr`, `web_app` — both stale since the v2 port rewrote every module), and `Taskfile.yml`'s `publish` treats a missing checksum as *changed*. Eighteen of twenty modules are blind patch-bumped on every run. The mechanism presents as change detection and behaves as an unconditional bump.

Everything needed to replace it has shipped: each module carries `identity/identity.cue` with a defaulted `Version` (0010's `modules-identity-authoring`), `opm module publish` gates and pushes from the committed tree, `opm module version set` is the single surgical writer, and `catalog_opm` has run the identical cutover end to end — release-please decides, the advance step writes identity on the release branch, publish asserts. This slice does that for 20 modules instead of one, and deletes the ledger.

Version decisions move to **per-module release-please**. D15 permits this explicitly rather than requiring it — *"Conventional commits stay a catalog convention rather than a requirement this decision imposes on `modules/`, which has no release-please today and would need per-module components"* — so adopting it is a choice within the decision, recorded as such. The one thing D15 forbids is release-please writing `identity.cue` directly through an `x-release-please-version` annotation, which would make it a second writer beside `version set`; the catalog's flow avoids that and this mirrors it.

## What Changes

- **Delete the ledger**: `versions.yml` entirely; `Taskfile.yml`'s `publish`, `publish:one`, `publish:dry`, `versions`, both copies of `compute_checksum`, both copies of `bump_version`, and the local-registry forcing stanzas (the catalog's precedent is to have *no* publish task at all — a local publish means pointing `OPM_REGISTRY` at the local registry deliberately). `fmt` / `vet` / `tidy` / `check` are untouched.
- **Per-module release-please**: `release-please-config.json` with one package per module directory (the 20 with a `cue.mod`; `cdi/` and `snapshot_controller/` are design-only stubs and are excluded), `release-type: simple`, per-module `component`, plus `.release-please-manifest.json` **seeded with each module's current declared version** — so `jellyfin` continues at 3.0.0, `k8up` at 3.0.0, `web_app` at 1.0.0, the rest at 2.0.0. Multi-path configs combine into one release PR by default; that stays.
- **New `release.yml`**, mirroring `catalog_opm`'s structure: a `release-please` job on push to `main` (opens/advances the release PR; **publishes nothing**) whose advance step reads the manifest on the release branch and runs `opm module version set <version> ./<module>` for every module whose declared version lags, committing as `github-actions[bot]`; and a `publish` job that sweeps the fleet, filtering **caller-side by a registry lookup** to modules whose declared version is unpublished, then `opm module publish ./<module>` for each. The sweep is D15's own idempotency mechanism and is what makes `modules-fleet-republish` a single run.
- **Publish stays disabled on push.** The publish job runs on `workflow_dispatch` only; widening its condition to the post-release push path is the deliberate enablement step that *is* `modules-fleet-republish`.
- **Keep, unchanged**: the GHCR token-exchange probe (`version_published` — its comment documents a real bug: GHCR rejects Basic auth, so a naive `curl -u` probe 401s and silently reads as *unpublished*), the cross-train major separation guard, and the `language.version` train check. Both guards retire with the `v1`/`v0_legacy` branches, which is deliberately **not** this slice.
- **Delete only the redundant guard**: the path-major vs version-major bash check, which `opm module publish` now enforces natively as a gate (0011 D18).
- **Fix a live staleness**: the collision guard compares `main` against `OTHER_BRANCH: v0_legacy`, but the train `main`'s majors actually have to dodge is the live `v1` branch — that is why `jellyfin` and `k8up` sit at major v3. Repointed to `v1`.
- **New `ci.yml`**: this repo runs *nothing* on pull requests today. Adds `task check` plus `opm module publish --dry-run` per module, tolerating an already-published refusal (the catalog's exact pattern), so a gate violation surfaces on the PR rather than at release.
- **Docs**: `CLAUDE.md`'s stale Registry section (claims push-publishing on `main`), its stale nine-row module table, the `versions.yml` bullets in `README.md`, and the "Adding a new module" recipe (never mentions `identity/identity.cue`) are corrected.

## Impact

- **Behavior**: version decisions become conventional-commit-driven per module; a commit touching several module directories bumps each of them, which is correct and worth knowing. The date-stamped fleet `release/<date>` tag and its rendered fleet table are replaced by per-module changelogs and releases.
- **Ledger, honestly**: this deletes one version ledger and adds another. They differ in direction — `versions.yml` was written *after* publish and read *before* it, a loop that drifted until 18 of 20 entries were empty; `.release-please-manifest.json` only feeds forward (release-please writes it → the advance step writes `identity.cue` → publish asserts), so it has no path by which to disagree with the artifact.
- **No post-publish verification**: `opm catalog registry check --compat` has no module equivalent (registry check is catalog-only). The modules pipeline ends at publish; noted, not worked around.
- **Ordering**: unblocks `modules-fleet-republish` (0010) — every module's declared version is currently unpublished, so the first sweep publishes all 20.
- **Not in scope**: deleting the `v1`/`v0_legacy` branches, retiring the two guards, or removing anything from GHCR — a separate change after the republish. `opm-kind-demo` vendors a clone of this Taskfile and carries its own copy of the checksum pattern; it goes stale here and is not this slice's to fix.
